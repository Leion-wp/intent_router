# Leion Delivery Proof Loop

## Goal

Turn technical delivery work into trust-building proof that helps close a pilot.

## Evidence sources

- `pipeline/product-1/*.intent.json`
- delivery docs in `docs/product-1/`
- run histories and diffs
- review checkpoints
- screenshots of the graph and approval flow

## Strongest proof themes

- governed automation instead of blind autonomy
- repeatable delivery workflows instead of ad hoc prompting
- explicit approval points on sensitive actions
- one control plane to keep shipping and improvement disciplined

## Proof assets to maintain

- one short demo script
- one before/after workflow narrative
- one evidence-backed claim
- one objection-handling section
- one list of missing proof
- one onboarding checklist
- one run export that shows approval evidence

## Demo script skeleton

1. start from a real issue or PR
2. show the Leion pipeline graph
3. show where AI writes and where human approval happens
4. show branch, patch, and validation steps
5. end on what is now repeatable for the team

## Current evidence-backed claim candidates

- Leion Delivery packages `Issue -> PR`, `PR review/fix`, and `release gate` as reusable flows.
- Approval and review remain explicit in the process.
- The same product can be improved from Codex without mixing control-plane logic into the runtime.
- The product can stay local-first while the control plane centralizes workflow metadata and proof.

## Missing proof

- real end-to-end run narrative on a repo
- screenshot set of the approval loop
- one concrete timing or effort comparison
- one case-study style pilot summary with explicit success criteria
